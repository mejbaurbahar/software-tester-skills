# Contributing

Thanks for helping testers and their AI agents get better. Skills, fixes, new commands, translations and corrections are all welcome.

## Quick start
```bash
git clone https://github.com/mejbaurbahar/software-tester-skills.git && cd software-tester-skills
python3 tests/validate_skills.py          # should pass on a clean checkout
```
Python 3.9+ and Bash are all you need; there are no dependencies to install.

## Add a skill
1. Create `skills/<kebab-case-name>/SKILL.md` (copy the template below). The directory name must match `name`.
2. Add the skill to the routing table in `skills/qa-skill-router/SKILL.md`.
3. Regenerate and validate:
   ```bash
   python3 scripts/build_adapters.py && python3 scripts/build_readme.py && python3 tests/validate_skills.py
   ```
4. Preview the website: `python3 scripts/build_site.py --serve` (http://127.0.0.1:8000).
5. Open a pull request. CI re-runs the checks and deploys the site after merge.

### Skill template
````markdown
---
name: my-skill-name
description: Use when <concrete situations and trigger words> — <what it covers in one sentence>.
license: MIT
metadata:
  category: code-level        # see CATEGORIES in scripts/stsk.py
  version: "1.0"
  tags: keyword, keyword, tool-name
---

# Human-Readable Title

## When to use / not use
## Procedure
## Commands and examples      <!-- real, tested, copy-paste -->
## Checklist / decision table
## Pitfalls

## Related
`other-skill`, `another-skill`
````

### Quality bar
- **Correct and specific.** Real tools, real flags, real limits. If you are unsure, test it or leave it out.
- **Actionable.** Someone (or an agent) should be able to follow it without further research.
- **Focused.** One job per skill; link to related skills instead of duplicating them. 60–150 lines; longer material goes in `references/`.
- **Description = routing.** Start with "Use when", include the words a user would actually type, stay under 1024 characters.
- **Defensive security only.** Security, fuzzing and load skills must require authorization, prefer staging and avoid real customer data or live credentials. Content that primarily enables attacks on systems the reader does not own will not be merged.
- No marketing tone, no filler, no unverifiable claims.

## Add or change a slash command
Edit `commands/<verb-noun>.md` (frontmatter `description` ≤ 100 chars and a quoted `argument-hint`; body written as instructions to the agent using `$ARGUMENTS` and naming the skills it uses). Then run `python3 scripts/build_adapters.py` so the Gemini, Cursor and Codex versions update.

## Generated files (do not edit by hand)
`README.md` blocks between `<!-- …:start/end -->` markers, `adapters/**`, `.claude-plugin/*.json`, and `_site/**` are generated by `scripts/build_*.py`. CI fails if they are stale.

## Commit and PR style
Small, focused PRs; imperative commit messages (`Add graphql-testing skill`). Explain what changed and how you verified any commands you added.

## Reporting problems
Use the issue templates: wrong or outdated guidance, a skill request, or an installer bug (include your OS, shell and tool).
